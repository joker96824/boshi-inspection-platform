# 机器人主控连接功能分析

## 一、web-one-robot 项目实现方式分析

### 1.1 架构概览

**web-one-robot 项目采用混合通信架构：**

```
前端 (Vue3) 
    ↓ (WebSocket)
ROS Bridge (rosbridge_server, ws://192.168.1.102:9090)
    ↓ (ROS2 话题)
机器人主控节点
    ↓ (HTTP API)
机器人主控服务 (后端API服务器)
```

### 1.2 关键实现点

#### 1.2.1 ROS 通信（前端直接连接）

**文件：`src/network/rosClient.js`**

- **连接方式**：前端使用 `roslib` 库直接连接 ROS Bridge WebSocket
- **连接地址**：`ws://192.168.1.102:9090`（rosbridge_server）
- **功能**：
  - 订阅 ROS 话题（如 `/global_robot_status`）
  - 发布 ROS 消息
  - 调用 ROS 服务
  - 自动重连机制（20秒间隔）

**关键代码：**
```javascript
// 连接到ROS服务端
connect(options = {}) {
  const { url = 'ws://192.168.1.102:9090' } = options;
  this.ros = new ROSLIB.Ros({ url: url });
}

// 订阅话题
subscribe(topic, messageType, callback) {
  const subscriber = new ROSLIB.Topic({
    ros: this.ros,
    name: topic,
    messageType: messageType
  });
  subscriber.subscribe(callback);
}
```

#### 1.2.2 机器人控制（HTTP API）

**文件：`src/api/robotControl.js`**

- **控制方式**：通过 HTTP PUT 请求控制机器人
- **API 端点**：
  - `/navigation/mode` - 设置导航模式（manual/auto）
  - `/navigation/move_to_pose` - 移动导航（充电、返航等）
  - `/navigation/manual` - 手动控制（前后左右移动）
  - `/chassis/set_safety` - 安全控制（软急停等）

**关键代码：**
```javascript
// 设置导航模式
export const setNavigationMode = (mode) => {
  return put('/navigation/mode', { data: { mode } });
};

// 手动控制
export const manualControl = (params) => {
  return put('/navigation/manual', { data: params });
};

// 移动导航
export const moveToPose = (params) => {
  return put('/navigation/move_to_pose', { data: { move_to_pose: params } });
};
```

#### 1.2.3 机器人状态订阅

**文件：`src/components/pages/RobotControl.vue`**

- **订阅话题**：`/global_robot_status`
- **消息类型**：`std_msgs/msg/String`
- **数据格式**：JSON 字符串，包含 `power.realtime_battery_level` 等字段

**关键代码：**
```javascript
subscribeRobotStatus() {
  rosClient.subscribe(
    '/global_robot_status',
    'std_msgs/msg/String',
    (message) => {
      const robotData = JSON.parse(message.data);
      if (robotData.power) {
        this.batteryLevel = robotData.power.realtime_battery_level;
      }
    }
  );
}
```

### 1.3 通信流程

1. **状态获取**：前端 → ROS Bridge → 机器人主控节点 → 返回状态
2. **控制命令**：前端 → HTTP API → 机器人主控服务 → 执行控制

## 二、当前项目实现方式分析

### 2.1 架构概览

**当前项目采用后端中转架构：**

```
前端 (WebSocket)
    ↓
后端 FastAPI (WebSocket Handler)
    ↓ (ROS2 Bridge)
ROS2 节点
    ↓
机器人主控节点
```

### 2.2 现有功能

#### 2.2.1 WebSocket 通信

**文件：`app/websocket/handlers.py`**

- **连接端点**：`/ws`
- **功能**：
  - 订阅/取消订阅消息类型
  - 发布 ROS2 消息（字符串、整数、浮点数、速度命令）
  - 获取 ROS2 话题列表
  - 测试任务（报警信息、机器人状态）

#### 2.2.2 ROS2 Bridge

**文件：`app/ros/ros2_bridge.py`**

- **功能**：
  - 发布 ROS2 消息（String, Int32, Float32, Twist）
  - 订阅 ROS2 话题（激光雷达、测试话题等）
  - 消息回调广播到 WebSocket

#### 2.2.3 ROS2 API

**文件：`app/api/v1/ros2.py`**

- **端点**：
  - `GET /api/v1/ros2/topics` - 获取话题列表
  - `POST /api/v1/ros2/publish/string` - 发布字符串
  - `POST /api/v1/ros2/publish/cmd_vel` - 发布速度命令
  - `GET /api/v1/ros2/status` - 获取状态

### 2.3 缺失功能

1. **机器人主控 HTTP API 代理**：没有实现类似 web-one-robot 的机器人控制 API
2. **机器人状态订阅**：没有订阅 `/global_robot_status` 话题
3. **机器人控制服务层**：没有封装机器人控制业务逻辑

## 四、实现方案对比

### 4.1 方案一：完全模仿 web-one-robot（前端直连 ROS）

**优点：**
- 实现简单，前端直接控制
- 延迟低，无需后端中转

**缺点：**
- 前端需要知道 ROS Bridge 地址
- 无法统一管理权限和日志
- 不符合当前项目的架构设计

### 4.2 方案二：后端代理 + WebSocket 中转（推荐）

**优点：**
- 符合当前项目架构
- 统一权限控制和日志记录
- 可以添加业务逻辑（如操作记录）
- 前端无需知道机器人主控地址

**缺点：**
- 需要后端实现 HTTP 客户端
- 延迟略高（多一层中转）

### 4.3 方案三：混合方案

**优点：**
- 状态订阅通过 ROS2（实时性好）
- 控制命令通过 HTTP API（统一管理）

**缺点：**
- 需要维护两套通信机制

## 五、推荐实现方案

### 5.1 架构设计

```
前端 (WebSocket)
    ↓
后端 FastAPI
    ├─ WebSocket Handler (状态推送)
    ├─ Robot Control Service (控制命令)
    │   └─ HTTP Client → 机器人主控服务
    └─ ROS2 Bridge
        └─ 订阅 /global_robot_status → 广播到 WebSocket
```

### 5.2 实现步骤

#### 步骤 1：配置机器人主控服务地址

**文件：`app/config/settings.py`**

```python
# 机器人主控服务配置
ROBOT_CONTROL_BASE_URL: str = "http://192.168.1.102:8080"  # 机器人主控服务地址
ROBOT_CONTROL_TIMEOUT: int = 10  # 请求超时时间（秒）
```

#### 步骤 2：创建 HTTP 客户端工具

**文件：`app/utils/robot_control_client.py`**

- 封装 HTTP 请求到机器人主控服务
- 处理超时和错误
- 支持重试机制

#### 步骤 3：创建机器人控制服务

**文件：`app/services/robot_control_service.py`**

- `set_navigation_mode(robot_id, mode)` - 设置导航模式
- `move_to_pose(robot_id, params)` - 移动导航
- `manual_control(robot_id, params)` - 手动控制
- `set_safety(robot_id, params)` - 安全控制

#### 步骤 4：创建机器人控制 API

**文件：`app/api/v1/robot_control.py`**

- `PUT /api/v1/robot-control/{robot_id}/navigation/mode`
- `PUT /api/v1/robot-control/{robot_id}/navigation/move_to_pose`
- `PUT /api/v1/robot-control/{robot_id}/navigation/manual`
- `PUT /api/v1/robot-control/{robot_id}/chassis/set_safety`

#### 步骤 5：在 ROS2 Bridge 中订阅机器人状态

**文件：`app/ros/ros2_bridge.py`**

- 订阅 `/global_robot_status` 话题
- 解析 JSON 数据
- 通过 WebSocket 广播 `robot_status` 消息

#### 步骤 6：添加操作记录

**文件：`app/services/operation_record_service.py`**

- 记录所有机器人控制操作
- 关联用户、机器人、操作类型等信息

### 5.3 数据流设计

#### 5.3.1 状态订阅流程

```
机器人主控节点
    ↓ 发布 /global_robot_status
ROS2 Bridge (订阅)
    ↓ 解析消息
WebSocket Handler
    ↓ 广播 robot_status
前端 (订阅 robot_status)
```

#### 5.3.2 控制命令流程

```
前端
    ↓ WebSocket / HTTP
后端 API
    ↓ 验证权限
Robot Control Service
    ↓ HTTP 请求
机器人主控服务
    ↓ 执行控制
机器人主控节点
    ↓ 反馈状态
ROS2 Bridge (订阅状态)
    ↓ 广播状态
前端 (接收状态更新)
```

## 六、关键技术点

### 6.1 HTTP 客户端选择

**推荐使用 `httpx`（异步 HTTP 客户端）：**
- 支持异步请求
- 支持连接池
- 支持超时和重试

### 6.2 机器人主控服务地址配置

**方案 A：全局配置**
- 所有机器人使用同一个主控服务地址
- 简单但不够灵活

**方案 B：按机器人配置**
- 在 `tb_robot` 表中添加 `control_url` 字段
- 每个机器人可以有不同的主控地址
- 更灵活，支持多机器人场景

**推荐：方案 B**

### 6.3 错误处理

- **网络错误**：重试机制（最多3次）
- **超时错误**：返回明确的错误信息
- **权限错误**：使用现有的权限系统
- **机器人离线**：检测连接状态，返回友好提示

### 6.4 状态同步

- **实时状态**：通过 ROS2 订阅获取
- **历史状态**：可选，存储到数据库
- **状态缓存**：在内存中缓存最新状态，减少数据库查询

## 七、注意事项

### 7.1 安全性

1. **权限控制**：只有授权用户才能控制机器人
2. **操作记录**：记录所有控制操作，便于审计
3. **频率限制**：防止恶意频繁发送控制命令
4. **参数验证**：严格验证控制参数，防止非法命令

### 7.2 性能

1. **异步处理**：使用异步 HTTP 客户端
2. **连接池**：复用 HTTP 连接
3. **超时设置**：合理设置超时时间，避免长时间等待
4. **状态缓存**：缓存机器人状态，减少重复查询

### 7.3 可扩展性

1. **多机器人支持**：支持同时控制多个机器人
2. **插件化设计**：不同机器人可以有不同的控制协议
3. **配置化**：机器人主控地址可配置
4. **日志记录**：详细的操作日志，便于问题排查
